# PicoRV32 SoC on Alveo U200

A minimal bare-metal RISC-V SoC that boots and prints **Hello, World!** over
UART, targeting the Xilinx Alveo U200 (xcu200-fsgd2104-2-e).

Everything is reproducible: TCL scripts recreate the Vivado project from
scratch, the Makefile drives the full firmware → bitstream flow in one command.

---

## Architecture

Pure RTL design — no Vivado Block Design.  Xilinx IPs are generated by
`create_project.tcl` and instantiated directly in `rtl/soc.v`.

```
sys_clk_p/n ─► IBUFDS+BUFG ─► clk ─────────────────────────────────┐
               (Unisim prims)         picorv32_axi_wrap (RTL)        │
                                        │  AXI4-Lite master          │
               power-on rst ─► rstn ───┤                            │
                                        │   AXI4-Lite decoder (RTL)  │
                                        │     │                      │
                                        │     ├─► axi_bram_ctrl_0 ──►blk_mem_gen_0
                                        │     │   (Xilinx IP)        (Xilinx IP)
                                        │     │   128 KB BRAM        init from .coe
                                        │     │
                                        │     └─► axi_uartlite_0
                                        │         (Xilinx IP)
                                        │         115200 8N1
                                        └─────────────────────────►  uart_txd/rxd
```

### Components

| Component | File / Source |
|-----------|---------------|
| PicoRV32 AXI wrapper | `rtl/picorv32_axi_wrap.v` (wraps `picorv32_axi`) |
| AXI4-Lite 1→2 address decoder | `rtl/soc.v` (RTL, ~50 lines) |
| AXI UART Lite (115200 8N1) | Xilinx IP `axi_uartlite:2.0`, generated by TCL |
| AXI BRAM Controller (128 KB) | Xilinx IP `axi_bram_ctrl:4.1`, generated by TCL |
| Block Memory Generator | Xilinx IP `blk_mem_gen:8.4`, init from `firmware.coe` |
| IBUFDS + BUFG clock buffers | Xilinx Unisim primitives in `rtl/top.v` |
| Power-on reset (256-cycle counter) | `rtl/top.v` |

### Memory map

| Address | Size | Description |
|---------|------|-------------|
| `0x00000000` | 128 KB | BRAM — code + data, reset vector |
| `0x40600000` | 4 KB | AXI UART Lite registers |

### UART register map (AXI UART Lite PG142)

| Offset | Name | Description |
|--------|------|-------------|
| `+0x00` | RXDATA | Received byte (read) |
| `+0x04` | TXDATA | Byte to send (write) |
| `+0x08` | STAT | `[3]` TX FIFO full, `[2]` TX FIFO empty, `[1]` RX FIFO full, `[0]` RX data valid |
| `+0x0C` | CTRL | `[1]` reset TX FIFO, `[0]` reset RX FIFO |

## Prerequisites

| Tool | Version | Purpose |
|------|---------|---------|
| RISC-V GCC | any recent | `riscv32-unknown-elf-gcc` or `riscv64-unknown-elf-gcc` |
| Vivado | 2022.1+ | Synthesis, implementation, bitstream |
| Python | 3.6+ | `bin2coe.py`, `bin2hex.py` |
| curl | any | Fetching `picorv32.v` from GitHub |

### Installing a RISC-V toolchain

**Ubuntu/Debian:**
```bash
sudo apt install gcc-riscv64-unknown-elf
```

**From source (SiFive/Crosstool-NG, 32-bit only):**
```bash
git clone https://github.com/riscv-collab/riscv-gnu-toolchain
cd riscv-gnu-toolchain
./configure --prefix=/opt/riscv --with-arch=rv32im --with-abi=ilp32
make -j$(nproc)
export PATH="/opt/riscv/bin:$PATH"
```

## Quick Start

```bash
# 1. Enter the project directory
cd /path/to/alveo

# 2. Fetch PicoRV32 + build firmware + create Vivado project + build bitstream
make all

# 3. Program the Alveo (hw_server must be running)
make program
```

Each step is also available individually:

```bash
make deps         # fetch rtl/picorv32.v from GitHub (pinned commit)
make firmware     # build firmware/ → firmware.elf / .bin / .coe
make project      # create Vivado project + block design (vivado/)
make bitstream    # synth → impl → write_bitstream → alveo_picorv32_soc.bit
make program      # program via Vivado hw_server
```

### Selecting a different Alveo variant

```bash
make all PART=xcu250-figd2104-2L-e   # Alveo U250
make all PART=xcu50-fsvh2104-2L-e    # Alveo U50
```

Update `constraints/alveo_u200.xdc` with the correct pin assignments for your
board (see the **Pin Constraints** section below).

## Step-by-Step Reproduction (manual)

### 1. Fetch PicoRV32

```bash
bash scripts/fetch_picorv32.sh
# produces rtl/picorv32.v
```

### 2. Build firmware

```bash
cd firmware
make
# produces firmware.elf  firmware.bin  firmware.coe  firmware.lst
cd ..
```

The `.coe` file is the BRAM initialisation file consumed by Vivado at
synthesis time.

### 3. Create the Vivado project

```bash
vivado -mode batch \
    -source scripts/create_project.tcl \
    -tclargs --part xcu200-fsgd2104-2-e \
             --coe $(pwd)/firmware/firmware.coe
```

This creates `vivado/alveo_picorv32_soc/`, generates the three Xilinx IPs
(`axi_uartlite_0`, `axi_bram_ctrl_0`, `blk_mem_gen_0`), and sets up the
pure-RTL project with `top` as the top module.

### 4. Run synthesis → implementation → bitstream

```bash
vivado -mode batch -source scripts/build.tcl
# produces alveo_picorv32_soc.bit
```

### 5. Program the device

Start `hw_server` on the machine connected to the Alveo (or on the same
machine if directly connected):

```bash
hw_server &   # or: hw_server -d (background daemon)
```

Then:

```bash
vivado -mode batch -source scripts/program.tcl
# or with a custom server address:
vivado -mode batch -source scripts/program.tcl \
    -tclargs --server 192.168.1.10:3121
```

### 6. Connect a terminal

The Alveo exposes the UART via its USB-C port (USB-UART bridge).  Find the
device node and connect at 115200 baud:

```bash
# Linux
ls /dev/ttyUSB*
minicom -D /dev/ttyUSB0 -b 115200 --noinit
# or
screen /dev/ttyUSB0 115200
# or
picocom -b 115200 /dev/ttyUSB0
```

Expected output after programming:

```
Hello, World!
PicoRV32 SoC running on Alveo
Echo mode (type to test RX):
```

## Pin Constraints

### Clock (verified for U200 and U250)

| Signal | Pin | Bank | Standard |
|--------|-----|------|----------|
| `sys_clk_p` | BJ44 | 74 | `DIFF_SSTL12` |
| `sys_clk_n` | BK44 | 74 | `DIFF_SSTL12` |

### UART

> **Verify these pins against your board revision before programming.**
> The Alveo board files are in `$XILINX_VITIS/data/boards/board_files/` or at
> https://github.com/Xilinx/XilinxBoardStore

| Signal | Pin | Bank | Standard | Notes |
|--------|-----|------|----------|-------|
| `uart_txd` | BB21 | 64 | `LVCMOS18` | FPGA TX → USB-UART bridge RX |
| `uart_rxd` | AT32 | 64 | `LVCMOS18` | USB-UART bridge TX → FPGA RX |

If your board uses different pins, edit `constraints/alveo_u200.xdc`.

### Reset

The `sys_reset_n` port is commented out in the XDC because many bare-metal
designs have no push-button reset.  In `scripts/create_project.tcl` the BD
connects `sys_reset_n` to a top-level port; you can tie it to `1'b1` in the
BD (constant IP) if you do not have an external reset.

## Changing the Firmware

1. Edit `firmware/main.c` (or any other firmware file).
2. Rebuild the COE: `make -C firmware`
3. Re-run synthesis (the BRAM init file changes, so a full re-run is required):
   ```bash
   make bitstream
   ```
   Or, to update only the COE in an existing project and re-run synthesis:
   ```bash
   cd vivado/alveo_picorv32_soc
   vivado alveo_picorv32_soc.xpr &
   # In Vivado GUI: Tools → Update Compile Order → Run Synthesis
   ```

## PicoRV32 CPU Configuration

The wrapper uses these parameters (edit `rtl/picorv32_axi_wrap.v` to change):

| Parameter | Value | Notes |
|-----------|-------|-------|
| `ENABLE_MUL` | 1 | Hardware MUL instruction |
| `ENABLE_DIV` | 1 | Hardware DIV instruction |
| `ENABLE_COUNTERS` | 1 | `rdcycle`, `rdtime`, `rdinstret` CSRs |
| `COMPRESSED_ISA` | 0 | No RVC (saves LUTs, sufficient for bare-metal) |
| `ENABLE_IRQ` | 0 | No interrupt support needed for Hello World |
| `STACKADDR` | `0x0002_0000` | Top of 128 KB BRAM |
| `PROGADDR_RESET` | `0x0000_0000` | Reset vector = start of BRAM |

## Troubleshooting

**`No RISC-V cross-compiler found`**
Install `gcc-riscv64-unknown-elf` (Ubuntu) or build from source (see above).

**`COE file not found`**
Run `make firmware` before `make project`.

**`picorv32_axi_wrap: module not found`**
Run `make deps` (or `bash scripts/fetch_picorv32.sh`) to download
`rtl/picorv32.v`.

**DRC error: `NSTD-1` / `UCIO-1` — unconstrained I/O on `M_AXI_*` ports**
This means Vivado synthesised `picorv32_axi_wrap` as the standalone top
module instead of `top`.  Re-run `make project` from scratch to recreate the
project with `set_property top top`.  If a stale `vivado/` directory exists,
run `make cleanall` first, then `make all`.

**`IP 'axi_bram_ctrl' version 4.1 not found`**
In Vivado 2024.x the IP version may be 4.1 or 4.2.  `create_project.tcl` will
fall back to the latest available version automatically.  If that also fails,
open Vivado → IP Catalog → search "BRAM" → note the exact VLNV and update the
`create_ip` call in `scripts/create_project.tcl`.

**Port-width mismatch on `bram_addr_a` / `addra`**
`axi_bram_ctrl_0` drives a **17-bit byte address** on its native BRAM port
(`bram_addr_a/b`).  `blk_mem_gen_0.addra/b` is a **15-bit word address**.
`rtl/soc.v` bridges them with `addra = bram_addr_a[16:2]` (drop the two
byte-select LSBs).  If your Vivado version generates a different address width,
check the stub in `vivado/.../ip/axi_bram_ctrl_0/hdl/` and update the
`wire [16:0] bram_addr_a/b` declarations and the `[16:2]` slice accordingly.

**UART shows garbage characters**
Check that your terminal is set to 115200 baud, 8 data bits, no parity, 1
stop bit (8N1).  Also verify the UART pin assignments in the XDC match your
board revision.

**Synthesis fails with timing errors**
PicoRV32 with RV32IM easily meets 100 MHz on UltraScale+.  If timing fails,
check that `create_clock` in the XDC is applied to `sys_clk_p`.
